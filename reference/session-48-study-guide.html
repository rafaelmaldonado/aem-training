Conceptos clave

WCAG (Web Content Accessibility Guidelines) reúne criterios del W3C para contenido web accesible. En esta sesión se comprueban algunos comportamientos concretos, sin declarar conformidad completa. SEO (Search Engine Optimization) ayuda a que los buscadores descubran y entiendan páginas públicas, sin garantizar un puesto en resultados. El foco marca el control activo para teclado; reflow adapta el contenido a un viewport estrecho. Una canonical expresa la URL preferida, las directivas robots controlan rastreo o indexación y un sitemap ayuda a descubrir URLs. La guía Markdown desarrolla las definiciones y su comprobación.

El caso

En una página desechable guide-48-lab, usa Core Title, Core Image y Core Text con un enlace a un mapa de práctica. Prepara tres defectos controlados: nivel incorrecto del título principal, enlace Click here y alt genérico para una imagen informativa. Son datos del ejercicio, no propiedades predeterminadas de WKND. Anota la URL y versión que realmente publicaste.

Práctica local · Author SDK y Publish

  1. Publica la página y ábrela como visitante. Con Tab, Shift+Tab y Enter, registra orden, activación y foco visible. Inspecciona el árbol de encabezados y los nombres accesibles.
  2. En Author, selecciona h1 para el Core Title principal sólo si el template no lo genera ya. Cambia el enlace a Open the river trail map y describe la imagen con un alt fiel, o márcala decorativa si realmente no aporta información. Publica y comprueba el HTML de Publish.
  3. Comprueba la página a 320 CSS px. El texto y los controles deben seguir disponibles sin scroll horizontal de página. Un fallo de CSS o del template se registra para corregir código; no se atribuye a un campo del autor.
  4. En Page Properties, revisa título, descripción, canonical, Robots Tags y Generate Sitemap. La interfaz depende del tipo de página. Inspecciona la respuesta y el <head> de Publish: <title>, canonical, meta robots o X-Robots-Tag. Revisa robots.txt y el sitemap publicado si el sitio los tiene configurados.
  5. Ejecuta Lighthouse sobre la misma URL y revisa el hallazgo concreto. Repite los controles manuales; la puntuación no sustituye el recorrido de teclado ni demuestra indexación.

Si sólo tienes Author, realiza el recorrido en preview e indica que SEO en Publish queda sin comprobar. La guía Markdown incluye preparación, datos esperados, limpieza y diagnóstico.

Señales SEO que deben concordar

SeñalComprobación
URL y respuestaLa página pública responde correctamente y entrega contenido indexable.
CanonicalUna URL absoluta con dominio y protocolo públicos correctos; evita localhost y duplicados.
RobotsSin noindex si la intención es indexar; rastreo permitido cuando corresponda.
SitemapLa URL incluida coincide con la canonical y está publicada.

Una canonical indica preferencia, y el buscador decide qué URL representa el contenido. Un sitemap ayuda a descubrir páginas, pero no garantiza indexación. robots.txt controla rastreo; para excluir resultados usa noindex con la página accesible al rastreador.

Lighthouse y Experience Audit

Lighthouse señala auditorías de accesibilidad y SEO para una URL. Experience Audit de Cloud Manager usa Lighthouse en pipelines de producción y presenta resultados para páginas configuradas. En este curso el reporte de Cloud Manager se estudia con documentación porque el acceso no está confirmado. Un resultado local no demuestra que se ejecutó la auditoría del pipeline.

Repaso con respuestas

  1. ¿Lighthouse alto prueba WCAG? No; hacen falta controles manuales.
  2. ¿Qué cambia al sustituir “Click here”? El propósito del enlace se entiende mejor.
  3. ¿Son iguales h1 y <title>? No; uno estructura contenido y el otro identifica el documento.
  4. ¿El sitemap garantiza indexación? No; revisa acceso, directivas, canonical y contenido.
  5. ¿Qué demuestra el SDK? El comportamiento y HTML de la instancia observada.
