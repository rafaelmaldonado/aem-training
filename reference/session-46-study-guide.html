Elegir la prueba que demuestra el riesgo

Conceptos y límites de pruebas unitarias, HTTP y UI aplicados a Models, servicios, servlets y permisos de AEM.

  • 30 minutos
  • Abrir slides
  • Guía Markdown completa
  • Práctica semanal voluntaria
Objetivo observable: nombrar el riesgo, la salida que lo revelaría, el resultado esperado y el entorno capaz de observarlo; después explicar el límite de la prueba elegida.

Qué demuestra una prueba

Un negativo comprueba una entrada o condición adversa con resultado definido. Cuando el producto la maneja bien, la prueba pasa. En AEM conviene separar la lógica ejecutada con mocks, la ruta HTTP instalada y la interacción de una persona con el navegador.

El caso

El TrainingMessageModel devuelve Weekend Guides cuando title falta o contiene sólo espacios. Las dos pruebas previas cubren título normal y propiedad ausente. La sesión añade un caso con title = " " en el archivo de prueba completo. En el proyecto local, sustituye el test anterior: no copies dos clases con el mismo nombre.

Demo local

  1. En el proyecto WKND local de las sesiones 18–19, sustituye el test por esta versión.
  2. Ejecuta mvn -pl core -Dtest=TrainingMessageTest test. Los tres tests deben pasar con el modelo intacto.
  3. En una rama desechable, elimina sólo title.trim().isEmpty() del getter y repite el comando. La prueba nueva debe fallar con esperado Weekend Guides y actual "".
  4. Restaura la condición y repite. Comprueba con git diff que la mutación temporal no quedó en el proyecto.

Si falla la creación del modelo o el setup de Maven antes de la aserción, resuelve ese fallo primero. La guía completa incluye el código, una petición HTTP opcional al Author SDK y preguntas de repaso.

Qué observar en SDK

Si el riesgo es la respuesta de una página, instala el componente en un Author SDK local y solicita una página de práctica real. Si el riesgo es ACL, prueba con la identidad técnica efectiva: una petición como administrador no demuestra el permiso del service user. Las pruebas del SDK observan esa instancia y configuración; no son evidencia de Publish o de un pipeline Cloud.
