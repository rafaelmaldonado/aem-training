Evolucionar un modelo CF sin romper consumidores

Añade referencias a una imagen y a otro fragmento mientras una página Sites conserva su resumen.

  • 30 minutos
  • Abrir slides
  • Guía Markdown completa
Objetivo observable: conservar el campo summary de un Guide ya consumido por una página, añadir heroImage como Content Reference y gear como Fragment Reference, inspeccionar valores faltantes en un CF anterior y planear sus dependencias de publicación.

El caso

En una rama de práctica de Author SDK, crea el modelo Training guide 44 con un campo Multi line text llamado summary y el modelo Training gear 44 con un campo Single line text llamado name. Crea el CF River walk con summary = Bring water. y el CF Daypack con name = Daypack. En una página guide-44-lab, configura el Core Component Content Fragment para mostrar sólo River walk.summary en la variación principal Main/Master. Registra el resultado antes de tocar el modelo. Adobe: configuración del componente.

Cambio del modelo

PropiedadTipoDecisión
summaryMulti line textConservar nombre, tipo y valor.
heroImageContent ReferenceAñadir opcional; restringir a imagen.
gearFragment ReferenceAñadir opcional; permitir el modelo Gear.

Content Reference enlaza otros recursos AEM, como imágenes. Fragment Reference enlaza otro CF de un modelo permitido. Un fragmento creado antes del cambio puede presentar los nuevos campos vacíos: ábrelo y compruébalo antes de completar las referencias. Editar un modelo utilizado puede afectar sus fragmentos; renombrar o borrar un campo existente puede romper consumidores que lo solicitan. Adobe: referencias anidadas · Adobe: cambios de modelos.

Práctica local en Author SDK

Preparar antes de clase: modelos habilitados en una configuración y permitidos por la Policy de una carpeta Assets de práctica; página y template con Core Component Content Fragment permitido. La guía Markdown detalla esta preparación y la limpieza.

  1. Crea ambos modelos, ambos CF y una página que muestre River walk.summary. Comprueba Bring water..
  2. Añade los dos campos opcionales al modelo Guide sin modificar summary. Guarda.
  3. Reabre River walk, registra el estado inicial de los campos nuevos y después selecciona una imagen de práctica y el CF Daypack. Comprueba que las referencias quedaron guardadas.
  4. Abre la página y su diálogo: el componente sigue seleccionando summary y mostrando Bring water.. La imagen y Gear no se convierten automáticamente en layout de página.
  5. Traza la cadena página → Guide → Gear y Guide → imagen. Si tienes Publish local, revisa el asistente de referencias y comprueba allá la página, ambos CF, ambos modelos y la imagen. Si no, registra esta cadena sólo como plan.

Repaso con respuestas

  1. ¿Son equivalentes los dos campos de referencia? No; uno enlaza otros recursos AEM y el otro CF de modelos permitidos.
  2. ¿Se rellenan solos los fragmentos anteriores? No se debe asumir; inspecciona cada fragmento afectado.
  3. ¿Por qué conservar summary? La página existente ya lo selecciona.
  4. ¿Qué demuestra Author? La selección y render locales observados; no el estado de Publish.
  5. ¿Qué depende de la publicación? Página, ambos CF, ambos modelos e imagen del caso.
