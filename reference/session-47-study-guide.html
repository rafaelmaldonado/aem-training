Pruebas de integración con Cypress

Un recorrido Author → Publish → visitante con datos, selectores y evidencia controlados.

  • 30 minutos
  • Abrir slides
  • Guía Markdown completa
Objetivo observable: especificar una ruta crítica y verificar en el navegador que el título aprobado en Author aparece en la página publicada. El ejemplo automatiza la visita anónima a Publish; la autoría y publicación son precondiciones controladas.

Estabilidad y aislamiento

La página de práctica tiene una sola instancia de TrainingMessage. Un atributo data-cy en el HTL localiza el componente sin depender del layout. Cypress aísla el contexto del navegador entre pruebas; los cambios en el repositorio y la publicación de AEM persisten. Prepara la versión correcta antes del test y restaura o retira el fixture después de la demo.

Ejemplo local

Instala el componente en Author y Publish, crea una página de práctica, guarda River walk 47 en Author y publica la página con sus dependencias. En una ventana privada, verifica primero que la URL de Publish muestra ese título. Después copia el spec Cypress 16 al proyecto local y ejecuta:

export CYPRESS_publishPageUrl='http://localhost:4503/content/<ruta-real>.html'
export CYPRESS_expectedTitle='River walk 47'
npx cypress run --spec cypress/e2e/training-message.cy.js

El spec hace cy.visit(publishPageUrl) sin credenciales de Author y exige que [data-cy="training-message"] h2 esté visible y tenga el texto esperado. La guía Markdown incluye la instalación local y la secuencia para mostrar una diferencia entre Author y Publish.

Registra la primera señal distinta antes de cambiar un timeout. Una espera fija no corrige un fixture que todavía no se publicó.

ui.tests en Cloud Manager

El módulo ui.tests empaqueta pruebas UI para Cloud Manager. Necesita contexto Docker, activación, datos del ambiente y reportes JUnit en REPORTS_PATH. Un pase local del spec no constituye evidencia del gate de pipeline.
