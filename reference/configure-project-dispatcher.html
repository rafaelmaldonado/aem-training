AEM Publish on Windows · Apache and Dispatcher in WSL

Configure Dispatcher in WSL.

Connect Ubuntu's Apache and Adobe Dispatcher module to local AEM Publish, then test a page from either an Archetype 57 project or the Adobe WKND tutorial.

What you need

  • AEM SDK Publish running on Windows at localhost:4503, with your project installed and one public .html page available. A page visible only on Author at port 4502 has not passed this check. Adobe: local AEM runtime
  • Ubuntu in WSL. If it is not installed, run wsl --install -d Ubuntu-24.04 in an elevated Windows terminal, restart Windows, and complete Ubuntu's first run. Microsoft: install WSL
  • Either the AEM Project Archetype 57 project generated with -DaemVersion="cloud" -DincludeDispatcherConfig="y", or a clone of Adobe WKND. Choose a real public page from your own project; the two starting points need not have the same content path.

This setup uses Adobe's standalone Linux Apache module and its sample dispatcher.any. It does not run or validate the project's Cloud dispatcher/src files. Adobe documents the Apache module installation; using it inside WSL with local Cloud SDK Publish is a course adaptation. Adobe: install Dispatcher for Apache · Adobe: Cloud configuration validation

1. Install Apache and confirm the Publish connection

In Ubuntu, install Apache and the tools used to identify the right Dispatcher package:

sudo apt update
sudo apt install apache2 curl openssl
uname -m
openssl version

Check whether Ubuntu can reach Publish through loopback. If it cannot, get the Windows host address used by WSL's default NAT network and try that address instead:

curl -i http://127.0.0.1:4503/content/YOUR_SITE/PAGE.html
ip route show | grep -i default | awk '{ print $3}'
curl -i http://WINDOWS_HOST_IP:4503/content/YOUR_SITE/PAGE.html

Replace the page path and WINDOWS_HOST_IP with your values. Continue with whichever address returns your published page. In WSL mirrored networking, loopback can reach Windows; in the default NAT mode, the Windows host IP is usually needed. If neither works, check that Publish is running and accepts connections from WSL before editing Dispatcher. Microsoft: WSL networking

2. Install the Dispatcher module

  1. Download the current Apache 2.4 Linux Dispatcher archive matching the architecture and OpenSSL version reported above. Use Adobe's Dispatcher release notes to choose the package. Extract it inside Ubuntu and read the archive's README for package details. Adobe: archive contents and installation
  2. Copy the archive's Dispatcher .so file to /usr/lib/apache2/modules/mod_dispatcher.so. Copy its Publish sample dispatcher.any to /etc/apache2/dispatcher.any. Use sudo for these system paths. Keep the sample as the starting configuration; your project's dispatcher/src has a different layout. Adobe: Apache module files

3. Point the sample farm at Publish

Edit /etc/apache2/dispatcher.any. In its existing Publish farm, set the renderer's /hostname to the address that worked in step 1 and /port to 4503. Set /cache /docroot to /var/www/html, the document root of Ubuntu's default site. Keep the sample's filter and cache rules until the first request works. Ensure the farm's /virtualhosts accepts the Host used in the test below. Adobe: renders, virtual hosts, and cache root

4. Enable Dispatcher in Apache

Create /etc/apache2/mods-available/dispatcher.load:

LoadModule dispatcher_module /usr/lib/apache2/modules/mod_dispatcher.so

Create /etc/apache2/conf-available/dispatcher.conf:

<IfModule disp_apache2.c>
  DispatcherConfig /etc/apache2/dispatcher.any
  DispatcherLog /var/log/apache2/dispatcher.log
  DispatcherLogLevel 3
</IfModule>

Inside the existing <VirtualHost *:80> in /etc/apache2/sites-available/000-default.conf, add this Directory block:

<Directory /var/www/html>
  Options FollowSymLinks
  AllowOverride None
  Require all granted
  <IfModule disp_apache2.c>
    SetHandler dispatcher-handler
    ModMimeUsePathInfo On
  </IfModule>
</Directory>

Enable the module and configuration, give Apache write access to its local cache root, check syntax, and restart:

sudo a2enmod dispatcher
sudo a2enconf dispatcher
sudo chown -R www-data:www-data /var/www/html
sudo apache2ctl -t
sudo service apache2 restart

The syntax check must report Syntax OK. Adobe documents LoadModule, DispatcherConfig, SetHandler, and ModMimeUsePathInfo; Apache documents the syntax test. Adobe: Apache directives · Apache: apachectl

5. Test your project's page

From Ubuntu, request the same public page through Publish and through Apache. Start with its full /content/.../page.html path, replacing the path and Publish address with those confirmed in step 1:

curl -i http://WINDOWS_HOST_IP:4503/content/YOUR_SITE/PAGE.html
curl -i -H "Host: localhost" http://127.0.0.1/content/YOUR_SITE/PAGE.html

Then open this URL in a Windows browser, replacing the path with the same published page:

http://localhost/content/YOUR_SITE/PAGE.html

The browser should display the Publish page through Apache and Dispatcher in WSL. For comparison, http://localhost:4503/content/YOUR_SITE/PAGE.html goes directly to Publish on Windows. If the Ubuntu curl request works but the browser URL does not, check that port 80 on Windows is available and that WSL localhost forwarding is working. Microsoft: access WSL applications from Windows

The second curl response should serve the page through Dispatcher. Record its status and any Location header. If Apache returns a different result, inspect /var/log/apache2/dispatcher.log and /var/log/apache2/access.log. A Dispatcher filter rejection can appear as a 404; check the rule before broadening access. Apache selects virtual hosts using the request Host, while Dispatcher also matches the farm's /virtualhosts. Adobe: filter behavior · Apache: name based virtual hosts

Compare the project's source rules only after this request works: WKND already contains a WKND vhost, farm, and rewrites; an Archetype 57 Cloud project has its own generated baseline. Those files can show the intended Host, URL mapping, filters, and cache policy, but this standalone WSL installation must be configured in its own Apache and dispatcher.any files.
