Separar navegador, CDN y Dispatcher

Atribuir contenido antiguo a la primera capa divergente usando la misma petición y evidencia de caché.

  • Núcleo de 30 minutos · ampliable a 60
  • Descargar guía Markdown completa
  • Slides en inglés
Objetivo: si Publish y Dispatcher sirven B pero la URL pública muestra A, identificar la primera capa que diverge. Entrega GET, Host, URL, marcador A/B, hora, headers y evidencia del navegador o log de CDN.

Para 60 minutos, añade 15 de comparación en DevTools y 15 de variantes del caso. La evidencia CDN de abajo es simulada. El entorno local no reproduce la CDN administrada.

1. La primera respuesta distinta

La petición atraviesa navegador → CDN → Apache/Dispatcher → Publish. Un hit temprano impide llegar a las capas siguientes. Compara el mismo método GET, Host, path y query string; registra el marcador visible A/B. Un HTTP 200 no demuestra frescura. Caché en AEM Cloud — Adobe.

Los logs de CDN documentan HIT, MISS y PASS. Correlaciona la petición por hora, Host, URL y rid; observa también res_age y POP. Logging — Adobe.

2. Tres relojes de frescura

Cache-Control: max-age=300 permite al navegador tratar la respuesta como fresca durante 300 segundos y también puede influir en cachés compartidas. Surrogate-Control: max-age=3600 establece otra vigencia para la CDN administrada por Adobe. Dispatcher aplica sus propias reglas y puede usar headers de expiración si tiene TTL habilitado. Son cifras didácticas, no valores recomendados para toda página. Si la respuesta tiene Age: 900, ya superó los 300 segundos del navegador pero sigue dentro de los 3600 de CDN del ejemplo: una nueva GET puede obtener un HIT en CDN aunque la copia local haya vencido. Política de caché — Adobe · Dispatcher — Adobe.

Cache-Control: max-age=300
Surrogate-Control: max-age=3600

Captura también Age, Set-Cookie, status, hora y marcador. Age no identifica por sí solo la capa. Para comprobar contenido, usa GET: Adobe documenta que un HEAD con miss puede convertirse en GET hacia origen. HEAD en CDN — Adobe.

3. Privacidad, query y clientlibs

La CDN administrada no almacena respuestas con private, no-cache, no-store o Set-Cookie. Comprueba Dispatcher por separado: su configuración podría guardar una respuesta que la CDN no guarda. Evita reglas amplias que incluyan HTML privado. Contenido privado — Adobe.

La CDN considera la URL y query para su clave, aunque puede eliminar parámetros de marketing mediante transformaciones. Dispatcher tiene /ignoreUrlParams. Añadir ?v=123 puede crear otra entrada, ignorarse o impedir caché; no ubica de forma fiable la capa responsable. Conserva la URL original e inspecciona reglas efectivas. Parámetros CDN — Adobe.

En AEM Cloud, el versionado estricto de clientlibs usa un hash lc- en la URL. Si el estilo parece antiguo, inspecciona primero el HTML: ¿sigue apuntando al hash anterior? Entonces el HTML debe actualizarse en la capa que lo sirve. Si apunta al hash nuevo, revisa la petición del asset. Clientlibs — Adobe.

Caso guiado: B, B, A

Traza didáctica simulada; no es log Cloud real. La página /content/site/en/cache-lab.html cambió de A a B y se publicó.

Conclusión: Publish y Dispatcher sirven B. La GET pública independiente recibe A y su log indica HIT: la primera divergencia es CDN. El navegador recibió A por red. Revisa la vigencia o el mecanismo de purga para esa URL; no borres toda la caché para ocultar la causa. Purga CDN — Adobe.

Variantes: navegador A + GET pública B + memoria/disco → navegador. CDN MISS + público A + Dispatcher B → comprobar Host, ruta y origen. Dispatcher A + Publish B → sesión 33.

Comprobación guiada

  1. Abre DevTools Network y registra si la respuesta salió de memoria/disco o de red. Anota si hiciste reload o desactivaste caché.
  2. Solicita la misma URL pública con una GET sin cookies ni query añadida: curl -i 'https://www.example.test/content/site/en/cache-lab.html'. Sustituye dominio y path de ejemplo.
  3. Si tienes acceso autorizado a logs Cloud, busca la GET por hora, Host, URL y rid. Sin acceso, analiza la traza simulada sin presentarla como observación real.
  4. Compara con Publish y Dispatcher según las sesiones 31–33. Escribe la primera capa que devuelve una versión distinta y su prueba.

Repaso con respuestas

  1. ¿Deben durar lo mismo los dos headers? No; Adobe permite vigencias distintas para CDN y navegador.
  2. ¿200 con Age prueba HIT de CDN? No; correlaciona la GET con el campo cache del log.
  3. ¿Private protege Dispatcher? No necesariamente; comprueba sus reglas.
  4. ¿Sirve añadir una query aleatoria? No de forma fiable; las capas pueden tratarla distinto.
  5. ¿HTML con hash lc- viejo? Busca dónde quedó viejo el HTML antes de culpar al asset.
