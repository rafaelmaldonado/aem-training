De authoring a desarrollo AEM.

A seven-week path for six remote developers with frontend and authoring experience, building AEM technical foundations from the ground up.

  • 17 de agosto–2 de octubre de 2026
  • AEM Sites tradicional
  • 30 min en línea
  • 60–120 min de práctica
Formato diario: 3 min de recuperación, 2 min de objetivo, 12 min de slides, 8 min de demo, 3 min para explicar el ejercicio y 2 min de cierre. Después: 60–120 min de práctica asíncrona.

Course objective: Enable frontend-oriented developers to maintain, extend, test, prepare for delivery and troubleshoot traditional AEM Sites solutions on AEM as a Cloud Service.

La práctica es el núcleo. El tiempo restante de la ventana disponible de 2–4 horas se usa en proyecto integrador, lectura oficial o PR review, sin extender la sesión en línea.

Proyecto del curso: cada developer mantiene y extiende WKND mediante el escenario Weekend Guides en su propio repositorio y SDK. Abrir las 7 prácticas semanales →

Profundidad práctica: el tiempo que ya no se usa para ejecutar Cloud Manager se invierte en Dispatcher/caché local, decisiones HTL y Sling Models, seguridad, accesibilidad, rendimiento, regresión y troubleshooting.

Course outcomes

  • Explain how content and code travel from Author to the browser.
  • Read an AEM project structure and locate a change in the correct module.
  • Modify authorable components with HTL, dialogs, client libraries and Sling Models.
  • Trace and maintain reusable content across Experience Fragments, Content Fragments and MSM live relationships.
  • Build, test and review changes compatible with AEM as a Cloud Service.
  • Troubleshoot foundational AEM, Dispatcher and caching issues, and interpret supplied pipeline evidence.
  • Demonstrate individual proficiency through working artifacts and technical explanation.

Proyecto transversal

Cada developer elige una de dos rutas aprobadas: clonar el tutorial público WKND o generar el proyecto con AEM Project Archetype. Después publica ese baseline en su propio repositorio, trabaja con el AEM as a Cloud Service SDK, completa las mismas siete prácticas y conserva evidencia comparable. Cloud Manager se estudia sólo con material suministrado; no agregar SPA, Forms, Commerce, Headless o EDS al núcleo.

Revisión del viernes

Las seis entregas se revisan asíncronamente antes de la sesión. El viernes se usan 3 minutos de recuperación, 12 para dos demos rotativas, 10 para hallazgos comunes y una variación técnica, y 5 para feedback y siguiente comprobación.
