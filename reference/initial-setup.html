Initial development setup.

Prepare a local AEM Author environment and build the team repository before the first development lab.

  • Target: AEM Sites
  • AEM as a Cloud Service
  • Checked: August 13, 2026
Definition of done: you can start AEM Author at http://localhost:4502, build the repository successfully, install it locally, and open the project in the Sites console.

Course version baseline

Use these versions for the training workspace unless the team repository explicitly pins a different compatible version. The repository wins when it already exists.

1. Request access before installing anything

  • Adobe ID added to the correct Adobe organization.
  • Permission to download the AEM as a Cloud Service SDK.
  • Read/write access to the team's Git repository.
  • Development AEM Author URL and user access, if already available.
  • Cloud Manager access only if your role requires it; it is not needed for the first local lab.
  • VPN, proxy, certificate, and artifact-repository instructions from your organization.

Ask the architect for the team repository URL. Do not copy an SDK archive or credentials into Git or a shared chat.

2. Install and verify the development tools

Install the versions from the baseline using your organization's approved method. The repository remains authoritative when it pins a compatible version.

java --version
mvn --version
git --version
node --version
npm --version
  • JDK 21: use Oracle JDK 21 or Eclipse Temurin OpenJDK 21 and confirm that Maven reports the same Java installation. Oracle JDK is Adobe's recommended support baseline.
  • Maven 3.9.4: required for the multi-module AEM build and aligned with Cloud Manager.
  • Git: required for the team workflow and repository.
  • Node.js 24.18.1 and npm 11.16.0: local frontend baseline. If the POM uses frontend-maven-plugin, Maven downloads its separately pinned Node/npm versions for the build.

If any command fails, stop here and record the exact command and error. Do not install random global packages to work around it.

3. Download and start AEM Author

  1. Sign in to the Adobe Software Distribution portal.
  2. Open the AEM as a Cloud Service tab.
  3. Sort by Published Date in descending order and download the latest AEM SDK result.
  4. Unzip the SDK. Locate the Quickstart JAR.
  5. Create a dedicated aem-sdk/author directory outside the Git repository.
  6. Copy the Quickstart JAR there and rename it aem-author-p4502.jar.
  7. Start it from a terminal; do not double-click the JAR.

macOS or Linux:

mkdir -p ~/aem-sdk/author
cp /path/to/aem-sdk-quickstart-*.jar ~/aem-sdk/author/aem-author-p4502.jar
cd ~/aem-sdk/author
java -jar aem-author-p4502.jar

Windows PowerShell:

New-Item -ItemType Directory -Force "$env:USERPROFILE\aem-sdk\author"
Copy-Item "C:\path\to\aem-sdk-quickstart-XXX.jar" "$env:USERPROFILE\aem-sdk\author\aem-author-p4502.jar"
Set-Location "$env:USERPROFILE\aem-sdk\author"
java -jar aem-author-p4502.jar

When prompted, use admin as the local-only administrator password unless the architect specifies another value. First startup can take several minutes. Open http://localhost:4502.

4. Create or clone the WKND Project Archetype project

Use one shared baseline: the architect performs option A once and pushes the generated project. Learners use option B. Do not generate six independent repositories.

Option A · Architect only: generate the starter project

Generate the traditional AEM Sites project used by the WKND learning path with AEM Project Archetype 57:

mvn -B org.apache.maven.plugins:maven-archetype-plugin:3.3.1:generate \
  -DarchetypeGroupId=com.adobe.aem \
  -DarchetypeArtifactId=aem-project-archetype \
  -DarchetypeVersion=57 \
  -DappTitle="WKND Training" \
  -DappId="wknd" \
  -DartifactId="aem-guides-wknd" \
  -DgroupId="com.adobe.aem.guides" \
  -Dpackage="com.adobe.aem.guides.wknd" \
  -Dversion="1.0-SNAPSHOT" \
  -DaemVersion="cloud" \
  -DsdkVersion="latest" \
  -DfrontendModule="general" \
  -DincludeDispatcherConfig="y" \
  -DincludeExamples="n" \
  -Dlanguage="en" \
  -Dcountry="us" \
  -DsingleCountry="y"

Review the generated files. Create .cloudmanager/java-version with only 21, or verify that it already contains that value. Then commit the clean baseline and push it to the team repository. The finished Adobe WKND repository is a reference implementation, not the repository learners modify.

Option B · Learners: clone the shared project

git clone <repository-url>
cd aem-guides-wknd
git status

With AEM Author running, build and install the complete project:

mvn clean install -PautoInstallSinglePackage

The first build downloads dependencies and can take longer. It must end with BUILD SUCCESS. This profile targets local Author on port 4502. If the project README defines a different command, use the repository command instead.

5. Verify the result

  • Sites console opens and the project site is visible.
  • Package Manager shows the project's installed packages.
  • The terminal shows BUILD SUCCESS.
  • git status does not show generated build output as new source files.

Stop AEM with Ctrl+C in the terminal that started it, and wait for shutdown to finish.

Troubleshooting

SymptomCheck first
AEM does not startRun from the terminal, confirm the JDK version, and verify port 4502 is free.
Maven uses the wrong JavaRead the Java runtime shown by mvn --version; fix the approved JDK configuration.
Dependency download failsCheck VPN, proxy, certificates, and the organization's Maven settings.
Build succeeds but nothing appearsConfirm Author is on 4502 and that the install profile completed without authentication errors.
Repository command differsFollow the repository README and report the difference to the architect.

Not required yet

Do not configure local Publish, Dispatcher Tools, Adobe I/O CLI, or Cloud Manager during this initial setup. The course introduces them before they are used.
