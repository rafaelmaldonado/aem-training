The tutorial documentation still contains examples generated with older archetype and Java versions. The course setup guide is authoritative: use its Archetype 57 command, JDK 21 and Maven 3.9.4. Do not copy an old generation command from a tutorial chapter.

Product scenario

The team inherits WKND and receives a request for a new Weekend Guides area. Authors must create guide pages and reusable cards without code changes. Visitors must browse accessible, responsive guide content. The implementation must be testable, cache-safe and deployable through an AEMaaCS pipeline.

  • An editable Guide Page template with controlled policies.
  • A Guide Card proxy component with a clear empty state.
  • A Guide List that can retrieve and order guide pages.
  • Responsive styling, keyboard access and useful metadata.
  • Tests, permissions, Dispatcher rules, deployment checks and runbook.

Repository strategy

  1. Generate the starter once using the command in the setup guide; record Archetype 57 and the generation properties in the training README.
  2. Push the generated baseline to an organization-owned repository. Keep adobe/aem-guides-wknd read-only as the finished reference.
  3. Create a protected training/main baseline. Each item uses feature/<id>-short-name.
  4. Change the sample content filter to mode="merge" before learners author content, so builds do not overwrite their work.
  5. Require one primary owner and one asynchronous reviewer. The next contributor number reviews: P1 → P2, P2 → P3, …, P6 → P1.
  6. Keep each PR to one backlog item. A screenshot alone is not acceptance; include the changed behavior and the check used.

Definition of done

  • Acceptance criteria pass in a fresh local SDK or the shared Development environment.
  • mvn clean verify succeeds and the PR contains no generated target files or secrets.
  • The owner supplies author and visitor evidence, plus the relevant test or diagnostic output.
  • The reviewer leaves at least one evidence-based observation and the owner resolves it.
  • The owner can explain where the change lives, why it belongs there and one remaining risk.

Capacity and rotation

Each item is sized for approximately 60–120 minutes of core practice. If an item is larger, split it before work begins. Primary ownership rotates each week so frontend experience does not become permanent frontend ownership. The architect reviews architecture and evidence but is not counted as delivery capacity.
