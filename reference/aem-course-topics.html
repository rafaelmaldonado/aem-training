Seven weeks · 35 sessions · English

AEM Sites training.

A practical path from AEM fundamentals to independently maintaining, testing and troubleshooting traditional AEM Sites solutions.

  • August 17–October 2, 2026
  • 30-minute live sessions
  • 60–120 minutes of practice
  • Individual repository and SDK
Course objective: enable frontend-oriented developers to maintain, extend, test, prepare for delivery and troubleshoot traditional AEM Sites solutions on AEM as a Cloud Service.

Schedule: Monday through Friday, August 17–October 2, 2026. Dates assume regular weekdays; move a session within its week if a local holiday applies.

Learning outcomes

  • Explain how content and code travel from Author to the browser.
  • Read an AEM project structure and locate a change in the correct module.
  • Modify authorable components with HTL, dialogs, client libraries and Sling Models.
  • Build, test and review changes compatible with AEM as a Cloud Service.
  • Troubleshoot foundational AEM, Dispatcher and caching issues, and interpret supplied pipeline evidence.
  • Demonstrate individual proficiency through working artifacts and technical explanation.

Practice model

Every developer uses the same selected WKND starting method—Adobe's public repository or the AEM Project Archetype—then completes the same weekly practice in an individual repository and local AEM SDK. The brief is released Monday, evidence is due Thursday and Friday is a review session. Cloud Manager is theory-only and uses supplied diagrams and anonymized evidence; no access or deployment is required.

Hands-on depth: time previously reserved for cloud execution is invested in local Dispatcher and caching, HTL and Sling Model decisions, security, accessibility, performance measurement, regression testing and troubleshooting.

Friday review

All six submissions are reviewed asynchronously. The 30-minute live session uses a retrieval question, two rotating demonstrations, common findings, one understanding check and concrete feedback for the next attempt.

Week 1 · Mental model and environment · August 17–21

  1. Mon, Aug 17 — AEM Sites from the ground up: AEMaaCS, Author, Publish, Dispatcher/CDN, content and code.
  2. Tue, Aug 18 — Local SDK, Maven and repository modules: core, ui.apps, ui.content, ui.config, all, dispatcher.
  3. Wed, Aug 19 — JCR, nodes, properties, resources and the separation of /apps, /content and /conf.
  4. Thu, Aug 20 — Sling resolution: URL → resource → resource type → script.
  5. Fri, Aug 21 — Weekly practice review: baseline and first technical diagnosis.

Week 2 · Maintainable authoring · August 24–28

  1. Mon, Aug 24 — Pages, editable templates, template types and initial structure.
  2. Tue, Aug 25 — Policies, allowed components, the Style System and author responsibilities.
  3. Wed, Aug 26 — Components, Granite UI dialogs and property persistence.
  4. Thu, Aug 27 — Assets, references, the Image Component, responsive images and alternative text.
  5. Fri, Aug 28 — Weekly practice review: authoring and content modeling.

Week 3 · Frontend development in AEM · August 31–September 4

  1. Mon, Aug 31 — HTL: expressions, attributes, conditions, lists, templates and context-aware escaping.
  2. Tue, Sep 1 — Client Libraries: categories, dependencies, embed, loading and debugging.
  3. Wed, Sep 2 — Core Components and the proxy pattern; sling:resourceSuperType.
  4. Thu, Sep 3 — Responsive behavior, accessibility, states and the empty author experience.
  5. Fri, Sep 4 — Weekly practice review: vertical frontend integration.

Week 4 · Essential backend for frontend developers · September 7–11

  1. Mon, Sep 7 — Java and OSGi in AEM: bundles, services, components and lifecycle.
  2. Tue, Sep 8 — Sling Models: adaptables, injection, optionality, getters and boundaries.
  3. Wed, Sep 9 — OSGi services and environment-specific configuration.
  4. Thu, Sep 10 — Resource API, servlets and when not to create an endpoint.
  5. Fri, Sep 11 — Weekly practice review: Sling Model testing and backend behavior.

Week 5 · Maintenance and investigation · September 14–18

  1. Mon, Sep 14 — Cloud-compatible structure: mutable content, immutable code and packages.
  2. Tue, Sep 15 — Logs, bundles, components, configurations and diagnostic tools.
  3. Wed, Sep 16 — Workflows, launchers, jobs and cloud limitations.
  4. Thu, Sep 17 — Search, QueryBuilder/Oak, indexes and signs of an expensive query.
  5. Fri, Sep 18 — Weekly practice review: maintenance simulation.

Week 6 · Production quality and delivery constraints · September 21–25

  1. Mon, Sep 21 — Cloud delivery mental model: programs, environments, repositories, pipelines and quality gates; theory from supplied evidence.
  2. Tue, Sep 22 — Local Dispatcher and caching lab: virtual hosts, filters, rewrites, headers and invalidation.
  3. Wed, Sep 23 — Permissions, service users, output security, validation and secrets.
  4. Thu, Sep 24 — Accessibility, SEO, performance measurement and risk-based testing.
  5. Fri, Sep 25 — Weekly practice review: local production readiness and theoretical delivery defense.

Week 7 · Capstone and knowledge transfer · September 28–October 2

  1. Mon, Sep 28 — Plan an individually owned final increment with observable acceptance criteria.
  2. Tue, Sep 29 — Capstone implementation using established HTL, Sling Model and Core Component patterns.
  3. Wed, Sep 30 — Review, defects, regression testing and hardening.
  4. Thu, Oct 1 — Individual practical assessment with a small live variation.
  5. Fri, Oct 2 — Final practice review: demo, technical defense, retrospective and 30-day plan.

Scope

Traditional AEM Sites on AEM as a Cloud Service. Edge Delivery Services, Headless, Forms and Commerce are outside the core curriculum.
