Eight weeks · 40 sessions · English

AEM Sites training.

A practical path from AEM fundamentals to independently maintaining, testing and troubleshooting traditional AEM Sites solutions.

  • 30-minute live sessions
  • 60–120 minutes of practice
  • Individual repository and SDK
Course objective: enable frontend-oriented developers to maintain, extend, test, deploy and troubleshoot traditional AEM Sites solutions on AEM as a Cloud Service.

Learning outcomes

  • Explain how content and code travel from Author to the browser.
  • Read an AEM project structure and locate a change in the correct module.
  • Modify authorable components with HTL, dialogs, client libraries and Sling Models.
  • Build, test, review and deploy changes compatible with AEM as a Cloud Service.
  • Troubleshoot foundational AEM, Dispatcher, caching and pipeline issues.
  • Demonstrate individual proficiency through working artifacts and technical explanation.

Practice model

Every developer starts from the same read-only WKND baseline, then completes the same weekly practice in an individual repository and local AEM SDK. The brief is released Monday, evidence is due Thursday and Friday is a review session. There are no cross-repository delivery dependencies. When a shared AEMaaCS environment is unavailable, cloud deployment and recovery are taught with local checks, Dispatcher Tools and supplied anonymized pipeline evidence.

Friday review

All six submissions are reviewed asynchronously. The 30-minute live session uses a retrieval question, two rotating demonstrations, common findings, one understanding check and concrete feedback for the next attempt.

Week 1 · Mental model and environment

  1. AEM Sites from the ground up: AEMaaCS, Author, Publish, Dispatcher/CDN, content and code.
  2. Local SDK, Maven and repository modules: core, ui.apps, ui.content, ui.config, all, dispatcher.
  3. JCR, nodes, properties, resources and the separation of /apps, /content and /conf.
  4. Sling resolution: URL → resource → resource type → script.
  5. Weekly practice review: baseline and first technical diagnosis.

Week 2 · Maintainable authoring

  1. Pages, editable templates, template types and initial structure.
  2. Policies, allowed components, the Style System and author responsibilities.
  3. Components, Granite UI dialogs and property persistence.
  4. Assets, references, the Image Component, responsive images and alternative text.
  5. Weekly practice review: authoring and content modeling.

Week 3 · Frontend development in AEM

  1. HTL: expressions, attributes, conditions, lists, templates and context-aware escaping.
  2. Client Libraries: categories, dependencies, embed, loading and debugging.
  3. Core Components and the proxy pattern; sling:resourceSuperType.
  4. Responsive behavior, accessibility, states and the empty author experience.
  5. Weekly practice review: vertical frontend integration.

Week 4 · Essential backend for frontend developers

  1. Java and OSGi in AEM: bundles, services, components and lifecycle.
  2. Sling Models: adaptables, injection, optionality, getters and boundaries.
  3. OSGi services and environment-specific configuration.
  4. Resource API, servlets and when not to create an endpoint.
  5. Weekly practice review: Sling Model testing and backend behavior.

Week 5 · Maintenance and investigation

  1. Cloud-compatible structure: mutable content, immutable code and packages.
  2. Logs, bundles, components, configurations and diagnostic tools.
  3. Workflows, launchers, jobs and cloud limitations.
  4. Search, QueryBuilder/Oak, indexes and signs of an expensive query.
  5. Weekly practice review: maintenance simulation.

Week 6 · Delivery on AEM as a Cloud Service

  1. Programs, environments, services, repositories and the delivery Git workflow.
  2. Cloud Manager, pipelines, quality gates and log analysis.
  3. Dispatcher: virtual hosts, filters, rewrites and caching.
  4. CDN, headers, invalidation and the path of a cache miss.
  5. Weekly practice review: deployment and recovery rehearsal.

Week 7 · Production quality

  1. Users, groups, permissions, service users and least privilege.
  2. Output security, validation, CSRF/XSS and secrets.
  3. Accessibility, SEO and semantics in authorable components.
  4. Performance and testing: unit, integration, UI and smoke tests.
  5. Weekly practice review: production readiness.

Week 8 · Capstone and knowledge transfer

  1. Plan an individually owned final increment with observable acceptance criteria.
  2. Capstone implementation.
  3. Review, defects and hardening.
  4. Individual practical assessment.
  5. Final practice review: demo, technical defense, retrospective and 30-day plan.

Scope

Traditional AEM Sites on AEM as a Cloud Service. Edge Delivery Services, Headless, Forms and Commerce are outside the core curriculum.
