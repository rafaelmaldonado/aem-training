Componente de estado y trabajo reintentable

El panel lee JCR con la identidad del visitante. Un workflow encola un Sling Job que falla antes de escribir, reintenta y aplica una sola vez v1 a guide-b.

  • Author SDK local
  • Consigna y criterios
Secuencia esperada: requestedVersion=v0 y sin processedVersion → Pending; cambiar a v1 → primer intento FAILED sin escritura → reintento OK con processedVersion=v1 y applyCount=1; replay → count sigue en 1.

2. Código del panel

Crea core/src/main/java/com/adobe/aem/guides/wknd/core/training/GuideStatusService.java. Conserva el package de tu proyecto. El servicio no abre un resolver técnico: recibe el resolver del componente y respeta sus permisos. Los paths se restringen a la fixture de laboratorio.

package com.adobe.aem.guides.wknd.core.training;

import org.apache.sling.api.resource.Resource;
import org.apache.sling.api.resource.ResourceResolver;
import org.osgi.service.component.annotations.Component;

@Component(service = GuideStatusService.class)
public class GuideStatusService {
    public Status read(ResourceResolver resolver, String controlPath, String guidePath) {
        String prefix = "/content/session-41-demo/guides/";
        if (!"/content/session-41-demo/control".equals(controlPath)
                || guidePath == null || !guidePath.startsWith(prefix)
                || guidePath.substring(prefix.length()).isEmpty()
                || guidePath.substring(prefix.length()).contains("/")) return null;
        Resource control = resolver.getResource(controlPath);
        Resource guide = resolver.getResource(guidePath);
        if (control == null || guide == null) return null;
        String requested = control.getValueMap().get("requestedVersion", String.class);
        if (requested == null || !requested.matches("v[0-9]+")) return null;
        String processed = guide.getValueMap().get("processedVersion", String.class);
        int count = guide.getValueMap().get("applyCount", 0);
        return new Status(guide.getName(), requested, processed, count);
    }

    public static final class Status {
        private final String name, requested, processed;
        private final int count;
        Status(String name, String requested, String processed, int count) {
            this.name = name; this.requested = requested;
            this.processed = processed; this.count = count;
        }
        public String getName() { return name; }
        public String getRequested() { return requested; }
        public String getProcessed() { return processed; }
        public int getCount() { return count; }
        public String getLabel() {
            return requested.equals(processed) ? "Up to date" : "Pending";
        }
    }
}

Crea GuideStatusModel.java en el mismo package. La única responsabilidad del Model es unir el recurso de componente, el diálogo y el servicio:

package com.adobe.aem.guides.wknd.core.training;

import javax.annotation.PostConstruct;
import org.apache.sling.api.resource.Resource;
import org.apache.sling.models.annotations.Model;
import org.apache.sling.models.annotations.injectorspecific.OSGiService;
import org.apache.sling.models.annotations.injectorspecific.Self;

@Model(adaptables = Resource.class)
public class GuideStatusModel {
    @Self private Resource resource;
    @OSGiService private GuideStatusService service;
    private GuideStatusService.Status status;

    @PostConstruct
    private void init() {
        status = service.read(resource.getResourceResolver(),
                resource.getValueMap().get("controlPath", String.class),
                resource.getValueMap().get("guidePath", String.class));
    }
    public GuideStatusService.Status getStatus() { return status; }
}

3. Código del reintento y replay

Reutiliza sin cambios el Process Step, el topic/cola ORDERED, el mapping y la ACL de la sesión 41. En una copia local de GuideBatchJobConsumer.java, cambia la lista y coloca la falla después de detectar un Guide pendiente, pero antes de escribir:

private static final String[] BATCHES = {"guide-b"};

// Dentro del for, inmediatamente DESPUÉS del bloque que compara
// version con processedVersion y hace continue si ya coincide:
if (job.getRetryCount() == 0) {
    LOG.warn("Week 11: fallo controlado antes de escribir job={}", job.getId());
    return JobResult.FAILED;
}

// Elimina el bloque original que fallaba después de guardar guide-a.
// Conserva processedVersion y applyCount en el mismo commit.

Este cambio conserva el manejo de LoginException y PersistenceException del consumidor original. El primer intento no modifica guide-b; el segundo aplica v1; un job nuevo con la misma versión se omite antes de la falla controlada por la comparación persistida. La cola local tiene dos reintentos con diez segundos de demora. La idempotencia de este laboratorio supone un único consumidor ordenado y sin escritores externos concurrentes.

Adapta la prueba existente para que sólo cree el mock de guide-b. Sus aserciones centrales deben quedar así:
