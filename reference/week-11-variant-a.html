Semana 11 · Variante A

Contenido reutilizable y localización

Una página Weekend Guides con una ficha que lee un Content Fragment, una promoción independiente en un Experience Fragment y una Live Copy con una excepción local.

  • Author SDK local
  • Consigna y criterios
Resultado que vas a mostrar: cambiar el fragmento cambia la ficha; cambiar el Experience Fragment cambia la promoción; una sincronización MSM actualiza contenido heredado y conserva el override local. Si hay Publish local, comprueba cada dependencia allí.

1. Preparar la página común

  1. Usa el proyecto AEM local que ya funciona. Anota su raíz de contenido, package Java, /apps/<proyecto> y la URL real de Author. No copies rutas WKND si tu proyecto usa Archetype.
  2. En una rama de práctica crea Weekend Guides con una editable template. En la policy del contenedor permite Title, Image, Text, Container, Content Fragment y Experience Fragment, o sus proxies ya instalados.
  3. Agrega Title como h1, Core Image con texto alternativo útil, un texto introductorio y un contenedor para las guías. Conserva la URL de la página para la demo.
  4. Comprueba la página a 320 CSS px y a un ancho de escritorio; recorre enlaces y controles con Tab. Inspecciona un evento de Data Layer sólo si los componentes instalados lo emiten.

La sesión 24 explica cómo habilitar modelos de fragmento y permitirlos en una carpeta de Assets. Las operaciones siguientes se hacen en Author; este repositorio de formación no es un proyecto Maven instalable.

2. Crear los datos del Guide

  1. En Tools → General → Configuration Browser crea o reutiliza una configuración de práctica con Content Fragment Models habilitado. En Tools → General → Content Fragment Models crea Week 11 Guide y habilítalo.
  2. En una carpeta Assets de práctica asigna esa configuración y permite el modelo en Properties → Policies. Crea un tag propio, por ejemplo training:activity/hiking.
  3. Crea River walk desde el modelo; usa una imagen de esa carpeta. Comprueba los nombres técnicos, no sólo las etiquetas visibles.

Para una solución sin Java, coloca el Core Content Fragment Component en un contenedor con estilo de ficha y selecciona Multiple Elements → guideTitle, summary. La referencia de imagen y el tag permanecen en el fragmento; ese componente no convierte automáticamente la ruta de imagen en una imagen de la ficha. Si la ficha debe mostrar también la imagen referenciada, usa el pequeño componente siguiente. El alt vacío del ejemplo es deliberado: la imagen de la ficha repite el mismo Guide cuyo título y resumen ya están en texto. La Core Image principal de la página sí lleva un alt informativo.

Crea ui.apps/src/main/content/jcr_root/apps/<proyecto>/components/guide-card/.content.xml y su diálogo. Cambia wknd y el package Java por los de tu baseline. La policy de la plantilla debe permitir este componente.

En core/src/main/java/.../training/GuideCardModel.java. El resolver es el de la petición; la ficha no eleva permisos para leer contenido oculto. El Model usa la API de Content Fragments en lugar de depender de la estructura interna jcr:content/data.

package com.adobe.aem.guides.wknd.core.training;

import javax.annotation.PostConstruct;
import com.adobe.cq.dam.cfm.ContentElement;
import com.adobe.cq.dam.cfm.ContentFragment;
import org.apache.sling.api.resource.Resource;
import org.apache.sling.models.annotations.Model;

@Model(adaptables = Resource.class)
public class GuideCardModel {
    private final Resource component;
    private String title;
    private String summary;
    private String imagePath;

    public GuideCardModel(Resource component) { this.component = component; }

    @PostConstruct
    private void init() {
        String path = component.getValueMap().get("fragmentPath", String.class);
        if (path == null || !path.startsWith("/content/dam/")) return;
        Resource source = component.getResourceResolver().getResource(path);
        ContentFragment fragment = source == null ? null : source.adaptTo(ContentFragment.class);
        if (fragment == null) return;
        title = text(fragment, "guideTitle");
        summary = text(fragment, "summary");
        String candidate = text(fragment, "image");
        if (candidate != null && candidate.startsWith("/content/dam/")) {
            imagePath = candidate;
        }
    }

    private static String text(ContentFragment fragment, String name) {
        ContentElement element = fragment.getElement(name);
        return element == null ? null : element.getContent();
    }

    public boolean isReady() { return title != null && !title.trim().isEmpty(); }
    public String getTitle() { return title; }
    public String getSummary() { return summary; }
    public String getImagePath() { return imagePath; }
}

En guide-card/guide-card.html. HTL escapa los valores de texto y trata la ruta del asset como URI:

<sly data-sly-use.card="com.adobe.aem.guides.wknd.core.training.GuideCardModel"/>
<article class="guide-card" data-sly-test="${card.ready}">
  <img data-sly-test="${card.imagePath}" src="${card.imagePath @ context='uri'}" alt="">
  <h2>${card.title}</h2>
  <p data-sly-test="${card.summary}">${card.summary}</p>
</article>
<p data-sly-test="${!card.ready}">Selecciona un Guide Content Fragment válido.</p>

Agrega el CSS mínimo a la clientlib ya usada por el sitio, si necesitas una presentación de ficha: .guide-card { border: 1px solid currentColor; padding: 1rem; }. No crees otra clientlib para una regla. En el diálogo de la ficha selecciona River walk. Cambia su summary en Assets y recarga la página: debe cambiar la ficha sin volver a editarla. Si el campo Tags debe verse, resuélvelo con el componente o el diseño de tu proyecto; en este ejemplo el tag se usa como metadato del Guide y se comprueba en el editor del fragmento.

Como comprobación negativa automatizada de la validación de ruta, agrega a los tests con AEM Mocks de tu proyecto un caso que cree un recurso de componente con fragmentPath=/etc/private, lo adapte a GuideCardModel y compruebe assertFalse(model.isReady()). Después prueba en Author un fragmento válido y otro inexistente: el segundo debe mostrar el estado vacío sin exponer una ruta ajena a DAM.

4. Experience Fragment y MSM

  1. Crea un Experience Fragment web de práctica con Title, Image y Button. En el botón usa un destino de práctica válido. Inserta el Experience Fragment Component en Weekend Guides y selecciona su variación, no sólo la carpeta.
  2. Edita el título en la fuente XF. Recarga la página: la promoción cambia; el campo summary del CF no cambia. Así verificas las dos fuentes independientes.
  3. Crea una Live Copy de la página en otra rama de práctica, o reutiliza una relación MSM existente. Registra el origen y la configuración efectiva. Cambia el texto introductorio en la fuente y ejecuta la sincronización/rollout disponible; confirma el cambio en el destino.
  4. En la Live Copy cancela herencia sólo para una propiedad visible, por ejemplo el título local del Hero, y pon un valor propio. Cambia de nuevo esa propiedad en origen y repite la sincronización. El valor local debe persistir mientras el texto aún heredado se actualiza. No cambies una configuración global de rollout para esta demostración.

La operación exacta disponible depende de si tu origen tiene blueprint configuration. Consulta la guía MSM de la sesión 43 antes de interpretar una opción ausente. No presupongas que la Live Copy traduce el contenido.

5. Publicar y resolver el caso “New route / Old route”

  1. Si existe Publish local, publica modelo, CF, asset, variación XF y página. Comprueba las referencias ofrecidas por el asistente y visita la URL real en Publish. No des por publicada una dependencia sólo porque la página se publicó.
  2. Cambia el título del CF a New route en Author. Publica únicamente la página para reproducir el caso. La ficha de Author puede leer el valor nuevo mientras Publish sigue leyendo Old route del CF publicado anteriormente.
  3. Comprueba la ruta fragmentPath guardada en el componente y abre ese mismo fragmento en ambos límites. La primera divergencia es el recurso CF. Publica el CF y verifica otra vez; si sigue antiguo, inspecciona la caché de entrega.
# Sustituye la ruta real; esta GET comprueba el HTML publicado, no el estado de Author.
curl -i 'http://localhost:4503/content/<tu-sitio>/<tu-pagina>.html'

Límite: el código de ficha supone un campo image de referencia única que devuelve una ruta DAM. Verifica el valor real en tu SDK antes de usarlo. Este material no registra una instalación ni un resultado en tu instancia.
