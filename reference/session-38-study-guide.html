1. Del PID al archivo ganador

Una configuración OSGi del proyecto se nombra <PID>.cfg.json; el PID suele ser el nombre completo de la clase. Una factory configuration agrega un identificador de instancia. La carpeta config, config.author, config.author.dev o equivalente admitido define los run modes de destino.

En Author con dev, si el mismo PID existe en config.author y config.author.dev, gana el archivo con más run modes coincidentes para el PID completo. Las propiedades no se mezclan. Si timeout sólo está en el archivo menos específico, el ganador no lo hereda; el valor indefinido depende del componente. Configuración OSGi — Adobe.

2. Resolver placeholders

FormaUsoOrigen
InlineValor no secreto estable; opción normal..cfg.json en Git.
$[env:CATALOG_URL]Valor no secreto que cambia entre dev o Publish y Preview.Variable del ambiente y servicio.
$[secret:CATALOG_KEY]API key o contraseña.Secreto fuera de Git.

En el SDK, una variable env puede definirse antes de iniciar Java. Un secreto local se lee desde un archivo sin extensión, cuyo nombre coincide con el placeholder, dentro del directorio señalado por org.apache.felix.configadmin.plugin.interpolation.secretsdir en sling.properties. No incluyas secretos reales en Git, capturas o logs. La prueba local no demuestra que la variable exista en Cloud Manager. Valores OSGi — Adobe · Variables — Adobe.

Preview hereda el archivo de Publish; no se crea config.preview. Un mismo placeholder puede resolverse a un valor diferente si la variable se define por separado para Publish y Preview. La carpeta responde qué archivo se eligió; la variable responde qué valor sustituyó al placeholder. Configuración OSGi — Adobe.

3. Caso guiado: local resuelve y Cloud no

Ficha didáctica inventada. El SDK con author,dev resuelve CATALOG_URL, pero el valor observado en Author Cloud difiere o conserva el placeholder. Comprueba en orden:

  1. PID exacto y servicio afectado.
  2. Archivo ganador por run modes y placeholder esperado.
  3. Configuración efectiva en AEM Developer Console para el ambiente y tier correctos.
  4. Variable definida en Cloud Manager para ese ambiente y servicio.
  5. Sólo entonces, causa sustentada por la comparación.

La slide 08 sugiere una variable ausente, pero hay que verificarla en Cloud Manager. Otras diferencias pueden tener otra causa. Developer Console en Cloud es de sólo lectura; el Web Console editable pertenece al SDK local. AEM Developer Console — Adobe.

Repaso con respuestas

  1. ¿Qué identifica el archivo? PID e instancia factory, si aplica.
  2. ¿Se hereda timeout del archivo menos específico? No; gana el archivo completo del mismo PID.
  3. ¿Cuándo usar inline? Para un valor no secreto estable; es la opción normal.
  4. ¿Dónde va una API key? En un secreto $[secret:...] fuera de Git.
  5. ¿Qué archivo lee Preview? El de Publish; la variable puede tener otro valor por servicio.
