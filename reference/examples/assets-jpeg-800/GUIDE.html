Choose the standard profile for this JPEG rule. It uses AEM as a Cloud Service's managed Asset Microservices. The aio commands below are for a separate custom Asset Compute worker project when the standard profile cannot express the transformation.

1. Create the standard Processing Profile

Use the AEM interface for a quick setup, or create the files in the next section for deployment from an AEM project. Both routes define the same profile.

  1. In an AEM as a Cloud Service Author environment, open Tools → Assets → Processing Profiles → Create.
  2. Name the profile Assets JPEG 800. On the Image tab, select Add New and enter:
FieldValue
Rendition file nameassets.800x800.jpeg
FormatJPEG
Width / Height800 / 800 px
Quality85
Included MIME typesimage/.*
Excluded MIME typesEmpty

Select Save. These are the fields in Adobe's standard Processing Profile instructions.

2. Create the profile as code in an AEM project

Use these paths relative to the root of your archetype-based AEM project. This training repository is not itself an AEM Maven reactor. Copy the XML into the matching paths under ui.content. If a target file already exists, merge the relevant entries or properties; keep its other content.

Processing folder

ui.content/src/main/content/jcr_root/conf/global/settings/dam/processing/.content.xml

<?xml version="1.0" encoding="UTF-8"?>
<jcr:root xmlns:cq="http://www.day.com/jcr/cq/1.0"
          xmlns:jcr="http://www.jcp.org/jcr/1.0"
          jcr:primaryType="cq:Page">
    <jcr:content jcr:primaryType="nt:unstructured" mergeList="{Boolean}true"/>
</jcr:root>

Profile definition

ui.content/src/main/content/jcr_root/conf/global/settings/dam/processing/assets-jpeg-800/.content.xml

<?xml version="1.0" encoding="UTF-8"?>
<jcr:root xmlns:cq="http://www.day.com/jcr/cq/1.0"
          xmlns:jcr="http://www.jcp.org/jcr/1.0"
          xmlns:sling="http://sling.apache.org/jcr/sling/1.0"
          jcr:primaryType="cq:Page">
    <jcr:content jcr:primaryType="nt:unstructured"
                 jcr:title="Assets JPEG 800"
                 sling:resourceType="dam/processing/profile"/>
</jcr:root>

JPEG rendition rule

ui.content/src/main/content/jcr_root/conf/global/settings/dam/processing/assets-jpeg-800/jpeg-800/.content.xml

<?xml version="1.0" encoding="UTF-8"?>
<jcr:root xmlns:cq="http://www.day.com/jcr/cq/1.0"
          xmlns:jcr="http://www.jcp.org/jcr/1.0"
          xmlns:sling="http://sling.apache.org/jcr/sling/1.0"
          jcr:primaryType="cq:Page">
    <jcr:content jcr:primaryType="nt:unstructured"
                 sling:resourceType="dam/processing/profile/rendition"
                 name="assets.800x800.jpeg"
                 fmt="jpeg"
                 wid="800"
                 hei="800"
                 qlt="85"
                 includeMimeTypes="image/.*"
                 excludeMimeTypes=""/>
</jcr:root>

Folder assignment

ui.content/src/main/content/jcr_root/content/dam/assets/_jcr_content/.content.xml

Merge processingProfile into the existing jcr:content node when this file already exists. A folder can have only one assigned Processing Profile; add this rendition to the existing profile if it must remain assigned.

<?xml version="1.0" encoding="UTF-8"?>
<jcr:root xmlns:cq="http://www.day.com/jcr/cq/1.0"
          xmlns:jcr="http://www.jcp.org/jcr/1.0"
          jcr:primaryType="nt:unstructured"
          cq:conf="/conf/assets"
          jcr:title="Assets"
          processingProfile="/conf/global/settings/dam/processing/assets-jpeg-800"/>

FileVault filter

ui.content/src/main/content/META-INF/vault/filter.xml

Merge these filter entries into the project's filter; do not replace its other roots or rules.

<?xml version="1.0" encoding="UTF-8"?>
<workspaceFilter version="1.0">
    <filter root="/conf/global/settings/dam/processing" mode="merge"/>
    <filter root="/content/dam/assets" mode="update_properties">
        <exclude pattern="/content/dam/assets/.*"/>
        <include pattern="/content/dam/assets/jcr:content(/.*)?"/>
    </filter>
</workspaceFilter>

3. Deploy, assign, and verify

  1. From the receiving AEM project root, run ./mvnw clean install and deploy its normal all package through Cloud Manager. Confirm Assets JPEG 800 appears under Tools → Assets → Processing Profiles.
  2. The folder XML above assigns the profile to /content/dam/assets. If you created it in the UI instead, select that folder in Assets → Files, open Properties → Asset Processing, choose Assets JPEG 800 under Processing Profile, and select Save & Close. You can also use Apply Profile to Folders from the profile list.
  3. Upload a 1600 × 600 image to the folder. Open its preview and Renditions rail; check that assets.800x800.jpeg exists at 800 × 300. Replace the original and check that the rendition updates.
  4. Upload a non-image file inside the folder and an image outside it; neither should receive this rendition. To process assets already present when the profile was assigned or changed, select them or their folder and use Reprocess Assets.

Subfolders inherit the profile unless they assign another one. The default AEM processing still runs alongside it. See Adobe's folder assignment and reprocessing instructions.

4. Develop a custom Asset Compute worker with aio

This section applies to a separate App Builder project. The standard JPEG rule above has no custom worker, so running aio from this directory cannot execute it.

  1. Create an App Builder project and workspace in the same Adobe organization as AEM. Configure Asset Compute, I/O Events, I/O Events Management, and Runtime access. Install Adobe I/O CLI and Node.js. See Adobe's setup requirements.
  2. From a parent directory, run aio app init asset-compute-app. Select DX Asset Compute Worker, Actions, and the Adobe Asset Compute Worker sample. Implement the transformation in asset-compute-app/actions/<worker-name>/index.js; Adobe's sample worker only copies the source.
  3. In the new app root, configure asset-compute-app/.env, the integration JSON as asset-compute-app/console.json or through ASSET_COMPUTE_INTEGRATION_FILE_PATH, and S3 or Azure test storage credentials. Keep credentials out of source control. The Development Tool uses this storage separately from AEM.

Run from asset-compute-app/:

npm install
aio app run

aio app run deploys the worker to Adobe I/O Runtime and opens the Development Tool at http://localhost:9000. Use the browser URL containing its generated devToolToken. Select a source image and set the tool's profile to the deployed worker URL and output name:

{
  "renditions": [
    {
      "worker": "<deployed-worker-url>",
      "name": "assets.800x800.jpeg"
    }
  ]
}

Select Run; inspect Renditions and Activation Logs. The worker must actually write a JPEG rendition for that name. Do not use aio app run --local: Asset Compute cannot call an action running only on your computer. See Adobe's Development Tool guide.

To launch only the Development Tool after deploying the worker, stop any aio app run session and run from the app root:

aio app deploy
aio asset-compute devtool

To execute the worker against a local file with Docker running:

aio asset-compute run-worker /path/to/source.jpg /tmp/assets.800x800.jpeg

If the aio asset-compute command is unavailable, install the Adobe CLI plugin with aio plugins:install @adobe/aio-cli-plugin-asset-compute. Adobe currently notes that the Development Tool does not work for custom workers created with OAuth credentials; check the authentication limitation.

Connect the worker to AEM

After aio app deploy, copy the endpoint URL from the deployment output. Edit the Processing Profile assigned to the target folder in AEM, open its Custom tab, select Add New, and enter the rendition name, worker endpoint, and included MIME types. Save and upload a new image. Keep the standard JPEG rule on the Image tab if it is also required; only one Processing Profile can be assigned to the folder. See Adobe's custom profile instructions.

Local SDK note

The local AEM SDK can confirm that a package installs, but it does not run Cloud Asset Microservices. A separate Java workflow can reproduce this JPEG output locally; its result does not validate the Cloud Processing Profile or a custom worker. Verify those flows in your AEM Cloud and App Builder environments.
