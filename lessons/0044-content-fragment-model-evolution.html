Class 44 · Week 9 · October 15, 2026

Evolve a Content Fragment Model safely

Add image and fragment references while the existing Sites page keeps rendering the same field.

  • 30-minute technical session
  • 12 PNG slides · Spanish presenter notes
  • Guía completa en español
Author SDK case: extend a disposable Guide model, inspect an older fragment with missing new values, and check the page's selected element. The UI views and image placeholder are illustrative; Publish dependencies are a plan until verified on a Publish instance.

Slide deck

Present these editable web slides, copy or download a PNG, or print the deck to PDF. Expand the Spanish notes for facilitation and sources.

Notas para LLM · slide 01

Conectar con la sesión 24: modelo, fragmento y componente son piezas distintas. El objetivo es añadir relaciones sin romper la página que ya muestra un resumen.

Notas para LLM · slide 02

El marcador de imagen es ilustrativo y está fuera del CF; no es evidencia de un SDK. La página y dos CF se preparan en Author antes de clase. La página consume sólo el summary del Guide; Daypack todavía no está relacionado. Es un laboratorio, no contenido WKND compartido.

Notas para LLM · slide 03

Inspeccionar el diálogo del Core Component. La variación principal se etiqueta Main o Master según el editor. El componente elige fragmento, elemento y variación. Fuente: Adobe · Configure dialog.

Notas para LLM · slide 04

Content Reference admite otros recursos AEM como imagen, página o Experience Fragment. Fragment Reference selecciona CF de modelos permitidos. Configurar ruta raíz para incluir la carpeta de práctica. Fuente: Adobe · Defining Content Fragment Models.

Notas para LLM · slide 05

La ruta segura del caso es aditiva: conservar summary y añadir campos opcionales. Adobe advierte sobre cambios a modelos existentes y sobre romper consultas que pidan nombres borrados o cambiados; aquí la comprobación principal es Sites. Fuente: Adobe · Content Fragment Models.

Notas para LLM · slide 06

Abrir de nuevo el CF existente para observar campos y valores. La ausencia de valor nuevo es una comprobación de laboratorio, no una migración asumida. Los editores pueden variar y el editor nuevo guarda automáticamente. Fuente: Adobe · Authoring Content Fragments.

Notas para LLM · slide 07

La profundidad del caso es una decisión de diseño, no un límite fijo de Adobe. La documentación ofrece protección contra autorreferencia y describe referencias anidadas. Mantener un salto permite explicar dependencias y autoría sin crear una cadena inútil. Fuente: Adobe · Nested content.

Notas para LLM · slide 08

La vista y el marcador de imagen son ilustrativos; no son una captura de AEM. El componente sigue en Single Text Element: summary. No prometer que la imagen ni Daypack se renderizan automáticamente. Para mostrar esos datos se necesitaría configurar otro consumidor o implementarlo y probarlo; eso queda fuera del caso. Fuente: Adobe · Content Fragment Component.

Notas para LLM · slide 09

Adobe exige que el modelo esté disponible al publicar un CF y puede incluirlo desde el asistente. La página, ambos fragmentos, modelos e imagen forman el plan de este caso. El asistente puede resolver algunas dependencias; comprobar la selección y el resultado. Fuente: Adobe · Publishing a Content Fragment Model y Adobe · Managing Content Fragments.

Notas para LLM · slide 10

Separar selección del picker, persistencia del CF, render de la página y estado de Publish. No editar el modelo otra vez antes de ubicar el primer punto que falla.

Notas para LLM · slide 11

Pedir al grupo que reconstruya la cadena: modelo Guide y Gear, CF River walk y Daypack, asset, componente y página. Preguntar qué se observa en Author y qué requeriría Publish.

Notas para LLM · slide 12

Abrir preguntas. Si hace falta, volver a la diferencia entre el valor de summary que muestra Sites y las referencias que permanecen en el CF. Cerrar sin añadir tema nuevo.
