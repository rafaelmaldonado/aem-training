Class 7 · Week 2 · Day 7 · August 25, 2026

Govern authoring choices without changing component code.

Trace policy resolution, control Allowed Components and connect semantic author choices to deployed CSS.

  • 30 minutes online
  • Policy diagrams
  • Local Author optional
Observable outcome: each developer can explain why a component is available or unavailable, trace its cq:policy mapping and show one semantic style backed by deployed CSS.

Architect preparation

  • Prepare a policy mapping example under /conf; the supplied diagram is sufficient.
  • Choose a small Guide Page component set and one intentionally disallowed component.
  • Prepare one semantic Style Name and its corresponding CSS class.
  • Do not depend on a live policy edit; repository and editor evidence may be captured beforehand.

Learning objectives

  • separate component capability from policy configuration;
  • trace a template location through cq:policy to its policy definition;
  • explain Allowed Components and policy defaults by scope;
  • connect Style Name, CSS class, client library and rendered wrapper.
