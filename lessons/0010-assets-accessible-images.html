Class 9 · Week 2 · Day 9 · August 27, 2026

Treat every image as content, delivery and accessibility.

Connect a managed DAM reference to Core Image behavior, responsive delivery and contextual alternative text.

  • 30 minutes online
  • Asset-to-browser contract
  • Local Author sufficient
Observable outcome: each developer can trace a Guide Page image from fileReference to its DAM asset, justify its alternative-text state and show responsive-delivery evidence in the browser.

Topic summary

A complete AEM image implementation connects three related contracts: a managed asset in DAM, the meaning of that asset in the current page and the bytes delivered to the browser. An image that looks correct may still reference the wrong asset, expose incorrect alternative text or transfer an unnecessarily large rendition.

The preferred implementation starts with a thin project proxy to the Core Image Component and configures supported behavior through policy. Verification then follows the same image from its stored fileReference through rendered HTML and accessibility semantics to the selected Network request.

  • Asset ownership: DAM owns the original binary, renditions and reusable metadata. The page component stores a fileReference rather than copying the binary.
  • Reuse before customization: a project proxy preserves the site-specific resource type while inheriting tested behavior from the installed Core Image version.
  • Contextual accessibility: informative, decorative, functional and complex images need different alternative-text behavior. The image’s purpose on this page—not its filename—drives the decision.
  • Metadata boundary: DAM metadata can provide a useful default, but it cannot determine whether the same asset is informative, decorative or functional in every context.
  • Responsive delivery: policy defines candidate widths, markup exposes them and the browser chooses a source based on layout and device density. CSS dimensions alone do not prove efficient transfer.
  • Lifecycle evidence: before moving, deleting or unpublishing an asset, inspect incoming references and verify the required asset and delivery behavior on Publish—not only in Author preview.

Architect preparation

  • Prepare one Guide Page image reference or use the supplied repository diagrams.
  • Prepare informative, decorative and missing or invalid states without depending on a live edit.
  • Use browser markup and network evidence to distinguish layout dimensions from transferred bytes.
  • Keep Web-Optimized Image Delivery theoretical; the local Adaptive Image Servlet is sufficient for the session.

Learning objectives

  • separate a managed DAM asset from the page component that references it;
  • use a project proxy to retain Core Image capability;
  • select alternative-text behavior from the image's purpose in context;
  • verify responsive candidates, selected requests and rendered dimensions;
  • inspect incoming references before asset lifecycle changes.

Guide Page image review

  1. Record the Image component path, its fileReference and the resolved DAM asset.
  2. Explain whether the image is informative, decorative, functional or complex in this page context.
  3. Inspect the rendered alt state for valid and missing or invalid authoring states.
  4. Inspect responsive candidates, the selected network request and rendered dimensions.
  5. Identify incoming references before proposing an asset lifecycle change.
