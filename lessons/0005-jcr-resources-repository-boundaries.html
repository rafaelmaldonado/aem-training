Class 3 · Week 1 · Day 3 · August 19, 2026

Read AEM as a resource tree.

Trace an authored page across JCR structure, Sling Resources and the repository boundaries that own content, configuration and code.

  • 30 minutes online
  • Read-only inspection
  • Local Author optional
Observable outcome: each developer can inspect an AEM page, distinguish nodes from properties and explain whether an item belongs to /content, /conf or /apps.

Architect preparation

  • Prepare one Repository Browser or CRXDE snapshot containing a WKND page and component instance.
  • Include visible examples of jcr:primaryType, jcr:title and sling:resourceType.
  • Prepare matching component and policy paths under /apps and /conf.
  • Use local Author only if it is already available; the lesson must work from supplied evidence.

Learning objectives

  • describe JCR as an addressable hierarchy of nodes and properties;
  • separate a cq:Page container from its jcr:content resource;
  • explain the Sling Resource and ValueMap application model;
  • classify repository paths by ownership and lifecycle.

Suggested speaking script

The complete talk track is available in speech.md.

Guided read-only inspection

  1. Mark the page path and identify the selected node.
  2. Classify three visible values as properties and one visible branch as a child node.
  3. Record jcr:primaryType and sling:resourceType.
  4. Follow the resource type to the matching component path under /apps.
  5. Identify one relevant template or policy path under /conf.

Evidence: one annotated screenshot or diagram containing the exact paths, two properties and a one-sentence lifecycle explanation for each repository boundary.
