Class 42 · Week 9 · October 13, 2026

Call an external service safely

See common outbound integrations, keep credentials server-side, and diagnose a bounded HTTP call from an OSGi service.

  • 30-minute technical session
  • 11 PNG slides · Spanish LLM notes on every slide
  • Guía completa en español
Local instructor demo: run the loopback HTTP stub and copyable Java in a local Author SDK. A manually started workflow invokes one GET and records 200, 401, 503 or read timeout. The panels in the slides illustrate expected evidence; they are not SDK screenshots.

Topic summary

Start with commerce, CRM and translation as illustrative integration needs. Define the HTTP contract and credential path, then compare page latency, connection/read waits, observed failures and a finite retry budget. Read the Java client before the local demo.

An OSGi service owns a fixed destination, a credential and separate connect/read timeouts. Its caller receives OK, RETRY or STOP; that classification does not itself schedule a retry. The example avoids a public servlet and does not block page rendering.

In the local demo, configure http://127.0.0.1:8765/ok with the disposable key training-demo-only. Start the workflow manually on an existing page. Repeat with the wrong key, /unavailable and /slow, changing the OSGi configuration before each new run. Compare HTTP responses with a transport timeout in error.log.

Notas para LLM · slide 04
  • En Cloud, guardar STATUS_API_KEY como variable secreta por ambiente. El archivo OSGi en Git referencia $[secret:STATUS_API_KEY]; el valor se resuelve en el runtime y el servicio lo envía en X-API-Key sólo al host HTTPS configurado. La credencial ficticia de la demo se escribe en ConfigMgr local; no debe copiarse a Cloud.
  • AttributeType.PASSWORD sólo oculta el campo en la interfaz de ConfigMgr; no es un almacén de secretos. No poner valores en Git, /content, HTML, JavaScript, parámetros de usuario ni logs. Desactivar redirecciones ayuda a mantener fijo el destino del header.

Fuentes: Adobe · OSGi secret values and Cloud Manager · Adobe · Managing secrets in AEM Cloud

Notas para LLM · slide 05
  • El ejemplo de 2,15 segundos es ilustrativo. Una llamada síncrona retrasa el render y ocupa su hilo. Si el dato tolera antigüedad, un job puede refrescarlo con una política de frescura y fallback. connectTimeout limita el establecimiento de conexión; readTimeout limita una lectura bloqueada. Notas para LLM · slide 06
  • Preparar stub y modelo antes de clase. Los cuatro registros ilustran ejecuciones separadas y resultados esperados, no capturas de Author. Pedir la predicción antes de cada instancia; /ok con clave correcta completa, 401 exige corregir la clave, 503 pide inspeccionar al proveedor y /slow señala la espera de lectura.
  • Un status HTTP y un fallo de transporte requieren investigaciones distintas. La clasificación didáctica agrupa todos los 5xx e IOException como RETRY, pero no prueba que repetir ayude. El Process Step hace un solo GET por instancia; RETRY no programa una segunda llamada.

Notas para LLM · slide 07
  • Es un ejemplo de política, no código de la demo: tres intentos totales, dos reintentos, nueve segundos nominales y límite global de diez. Los dos timeouts del cliente no implementan esos deadlines. Evitar multiplicar reentregas de job por reintentos HTTP. La secuencia POST es conceptual; la demo hace GET. Notas para LLM · slide 09
  • 127.0.0.1 en Cloud apunta a la propia instancia, no al stub del portátil. Comprobar URL y secreto efectivos, DNS y ruta de egress, TLS, status y contrato de datos. Advanced Networking depende del destino y requisitos del proveedor; éxito local no lo verifica. Registrar duración, resultado, intento e ID de correlación, sin credenciales ni payloads.
