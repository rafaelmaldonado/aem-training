Class 39 · Week 8 · October 8, 2026

Diagnose AEM Cloud with the right tool

Choose the evidence that tests a specific runtime hypothesis: logs, service state, repository content or a theoretical RDE reproduction.

  • 30-minute technical session
  • 10 PNG slides · Spanish LLM notes on every slide
  • Guía completa en español
Simulated case: all request results, logs, component names and repository states below are illustrative. No Cloud access or deployment is required.

Topic summary

Start with the failing tier, path and time. Cloud logs narrow the runtime error; Developer Console shows whether a bundle, component or required service reference is active; Repository Browser checks the visible content on that tier. The RDE slides explain how a team with access could reproduce and test a candidate correction, then validate it through the regular pipeline. The simulated case ends with a missing service reference, not a proven deployment cause.

  • Intención: delimitar el síntoma antes de atribuir una causa.
  • Explica: la misma ruta didáctica devuelve 200 en Author y 500 en Publish. Anota tier, hora y ruta; el 500 sólo indica fallo del lado servidor en esa petición.

Notas para LLM · slide 03
  • Intención: usar cada herramienta para una pregunta distinta.

Notas para LLM · slide 05
  • Intención: separar el estado del bundle del estado de sus componentes.
  • Explica: en la ficha inventada, wknd.core está activo, pero CatalogService está insatisfecho por la referencia obligatoria CatalogClient. Developer Console puede mostrar bundles, componentes, referencias y configuraciones del ambiente y tier seleccionados. Esa evidencia dirige la inspección al proveedor de la referencia y su configuración.
  • Límite: «referencia ausente» no demuestra aún si faltó un bundle, una configuración o una condición de activación. La consola en Cloud es evidencia de lectura; no presentes el Web Console local como interfaz productiva.

Notas para LLM · slide 06
  • Intención: comprobar la hipótesis de contenido ausente en el tier que falla.
  • Explica: Repository Browser es de sólo lectura. En el ejemplo, se observa /content/wknd/en/guides/jcr:content en Author y Publish. Por ello, un nodo completamente ausente deja de ser la explicación más probable y se continúa con el servicio insatisfecho.
  • Límite: ver el nodo no prueba que su render funcione, que las referencias estén publicadas ni que toda identidad pueda leerlo. Los permisos influyen en lo visible en Repository Browser.

Notas para LLM · slide 07
  • Intención: ubicar RDE como ambiente rápido de reproducción y validación, después de tener una hipótesis.
  • Explica: como flujo hipotético para un equipo con acceso, se intentaría reproducir el fallo con código, configuración y contenido comparables al ambiente afectado. Después se sincronizaría una corrección candidata y se comprobarían de nuevo la respuesta y el estado de CatalogService. La sincronización CLI hacia RDE evita la pipeline; una pipeline normal a Development aún debe pasar sus gates.
  • Límite: no hay acceso a RDE ni se hará una demostración. Un 200 hipotético en RDE no demostraría la causa en producción ni reemplazaría pruebas de stage. Coordina antes de resetear un RDE compartido; el reset elimina su código y contenido actuales.

Notas para LLM · slide 08
  • Intención: mostrar como referencia los comandos mínimos del flujo RDE descrito en la slide 07; no son pasos para ejecutar en esta clase.
  • Explica: aio login autentica; aio aem:rde:setup selecciona el programa y RDE; status comprueba disponibilidad; install sincroniza el artefacto ya construido; history muestra las instalaciones registradas. Sustituye <artifact.zip> por el paquete del proyecto. La instalación sin opción de servicio apunta a Author y Publish.
  • Límite: son comandos de referencia, no una ejecución registrada. Requieren AIO CLI, plugin RDE, permisos y un RDE seleccionado. No ejecutes install contra un RDE compartido sin coordinar; el flujo no pasa los gates de Cloud Manager.

Notas para LLM · slide 09
  • Intención: cerrar el diagnóstico con una conclusión delimitada por evidencia, no con una causa inventada.
  • Explica: «Publish devuelve 500; el log nombra CatalogService; la consola muestra CatalogClient ausente; el contenido base existe». El siguiente paso es averiguar por qué no se registra CatalogClient, probar una corrección en RDE y validarla luego por pipeline.
  • Límite: no afirmes que el 500 se corrigió ni que se desplegó nada; toda la ficha es didáctica.
