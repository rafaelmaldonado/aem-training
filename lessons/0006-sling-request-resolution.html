Class 4 · Week 1 · Day 4 · August 20, 2026

Follow the request, not a guess.

Trace a Sling request from URL to resolved Resource, request information, resource type hierarchy, selected handler and response.

  • 30 minutes online
  • Evidence-led inspection
  • Local Author optional
Observable outcome: each developer can justify every transition in a Sling request trace with an exact URL segment, Resource path, property or handler candidate.

Architect preparation

  • Prepare a captured request and matching repository evidence for one WKND page or component.
  • Include the resolved Resource path, RequestPathInfo, sling:resourceType and any sling:resourceSuperType.
  • Include the matching project component path and selected script or servlet.
  • Use local Author only if it is already available; the lesson must work from supplied evidence.

Learning objectives

  • explain why Sling resolves a Resource before selecting rendering code;
  • decompose a request into resource path, selectors, extension and suffix;
  • follow sling:resourceType and sling:resourceSuperType through the resource type hierarchy;
  • justify why a script or servlet is the most specific matching candidate.

Guided read-only request trace

  1. Record the request URL and HTTP method.
  2. Identify the resolved Resource path and decompose the remaining request information.
  3. Read sling:resourceType and any sling:resourceSuperType.
  4. List the relevant script or servlet candidates and identify the selected handler.
  5. Connect the handler to the observed response.

Evidence: one annotated trace containing the exact request, Resource path, request information, resource type hierarchy, selected handler and response.
