Antes del Día 1 · sin calificación

Diagnóstico inicial.

Treinta y cinco minutos asíncronos para ajustar la profundidad de las lecciones. No se consulta documentación.

  • 6 participantes
  • Respuesta individual
  • Sin reunión adicional
Importante: se evalúan dimensiones, no se etiqueta a la persona con un nivel único. El resultado no afecta una calificación.

1. Contexto personal · 5 min

  • Experiencia principal: frontend, Java/backend, QA/DevOps u otra.
  • Años aproximados trabajando con web y con AEM.
  • Una tarea de AEM que puedo realizar sin ayuda.
  • Una tarea de AEM que todavía no puedo realizar.
  • Accesos disponibles: Java, Maven, Git, Node, SDK y repositorio. Cloud Manager no es requisito.

2. Recuperación conceptual · 10 min

Responde en una o dos frases, sin buscar definiciones.

  1. ¿Qué diferencia práctica existe entre Author y Publish?
  2. ¿Qué ocurre desde que el navegador solicita una URL hasta que AEM devuelve HTML?
  3. ¿Para qué sirven JCR, Sling y OSGi?
  4. ¿Qué responsabilidades tienen HTL, un Sling Model y una client library?
  5. ¿Por qué se prefiere extender un Core Component mediante proxy en vez de copiarlo?
  6. ¿Qué debería cachear Dispatcher y qué no?

3. Lectura de proyecto · 10 min

Usa el repositorio real si está disponible; de lo contrario, un proyecto de ejemplo. Localiza y explica:

  • El componente y su diálogo.
  • El Sling Model asociado.
  • La inclusión de CSS o JavaScript.
  • La configuración dependiente del ambiente.
  • La forma de construir y desplegar.

No es necesario terminar todo. Marca dónde necesitaste ayuda.

4. Cambio práctico · 10 min

Elige una opción según tu perfil. Incluye cómo comprobarías el resultado y un riesgo que revisarías.

Frontend

Describe archivos y cambios para agregar una variante visual authorable a un componente existente.

Backend

Escribe o bosqueja un Sling Model que expone un título con valor alternativo.

QA / DevOps

Propón la comprobación mínima que impida que el cambio roto llegue a producción.
