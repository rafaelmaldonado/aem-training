Accessibility and SEO on one AEM page

Inspect visitor use and the signals delivered to crawlers.

  • 30-minute technical session
  • 10 downloadable PNG slides · Spanish presenter notes
  • Guía completa en español
Local case: review a disposable Sites page in Publish, fix authorable content, and inspect the delivered HTML. The UI view and sample public domain are illustrative. Cloud Manager results require a separate report.

Slide deck

Notas para LLM · slide 01

Conectar con la sesión 47: un título visible en Publish no demuestra que la página se pueda usar con teclado ni que sus señales SEO sean correctas. Esta clase observa una sola página de práctica y registra lo que entrega Publish.

Notas para LLM · slide 02

Definir WCAG antes de usar sus criterios. W3C publica WCAG; aquí se eligen comprobaciones concretas, no una auditoría completa de conformidad. SEO se aborda como señales técnicas de descubrimiento y comprensión, no como promesa de ranking. La accesibilidad se observa en tareas reales del visitante.

Notas para LLM · slide 03

Crear guide-48-lab en una carpeta desechable con Core Title, Core Image y Core Text. El enlace “Click here”, el alt genérico y el nivel incorrecto del título son defectos preparados para el ejercicio, no valores predeterminados de WKND. La interfaz que se muestra es ilustrativa.

Notas para LLM · slide 04

Foco es el control activo para la interacción de teclado. Comprobar orden, visibilidad y que no quede tapado. Reflow, según WCAG 1.4.10, se verifica a 320 CSS px para contenido de desplazamiento vertical; un viewport inicial de 1280 CSS px al 400 % de zoom es una forma de reproducirlo. El 200 % no equivale a esta comprobación. Registrar los casos que requieren una disposición bidimensional por su significado.

Notas para LLM · slide 05

La jerarquía de encabezados describe la estructura. Elegir h1 para el título principal sólo si el template no lo emite ya. Nombre accesible es el texto que anuncia la tecnología de apoyo para un control; el enlace debe comunicar su destino. El alt transmite el propósito de una imagen informativa. El Core Image puede heredar alt del DAM o marcar una imagen decorativa. Comprobar el HTML de Publish después de corregir Author. Si el problema está en HTL, CSS o template, registrar un cambio de código.

Notas para LLM · slide 06

Separar conceptos. Canonical expresa preferencia, no obliga al buscador. robots.txt limita rastreo; noindex controla la inclusión en resultados cuando el rastreador puede leerlo. El sitemap ayuda a descubrir URLs y debe anunciar la misma URL pública elegida. En AEM, Page Properties puede mostrar Title, Canonical Url, Robots Tags y Generate Sitemap según el tipo de página.

Notas para LLM · slide 07

Abrir la URL real de Publish y revisar status, HTML y headers. El dominio example.org es sólo una muestra. Comparar una canonical absoluta con la URL del sitemap real, si está configurado; revisar meta robots, X-Robots-Tag y robots.txt. Si la canonical sale con host o protocolo incorrectos, revisar Page Properties, Externalizer, mappings, X-Forwarded-Proto y personalizaciones del template. Una ejecución local no demuestra indexación real.

Notas para LLM · slide 08

Lighthouse audita una URL y sus hallazgos orientan la revisión. La cobertura automática no sustituye teclado, foco y reflow manuales. Adobe Experience Audit usa Lighthouse en pipelines de producción y presenta resultados para páginas configuradas. No se presupone acceso a Cloud Manager; un pase local no es evidencia del pipeline.

Notas para LLM · slide 09

Pedir que reconstruyan la evidencia mínima: URL y versión publicada, recorrido de teclado, árbol de encabezados, alt, viewport a 320 CSS px, head y sitemap si existe. Separar errores de contenido de fallos de template. Un pase local no demuestra indexación ni una auditoría de Cloud Manager.

Notas para LLM · slide 10

Abrir preguntas. Si hace falta, volver a la diferencia entre Page Properties y el HTML efectivamente entregado, o entre una puntuación automática y la navegación manual con teclado.
